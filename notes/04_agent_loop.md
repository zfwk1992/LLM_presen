# 04 · Agent Loop（Agent 循环）

![Agent loop](../llm_agent_animations_single_page/04d_agent_loop.gif)

> 这一页的 GIF 现在叫 `04d_agent_loop.gif`。它是比较抽象的总结图，建议先看 [04abc_agent_and_llm.md](04abc_agent_and_llm.md) 里更具体的三页（04a、04b、04c），再回来看这一页。

> **一句话**：Agent 就是把 LLM 放进一个循环里——想一步、做一步、看结果，直到它不再需要工具为止。

## 在演讲里的位置

这是第二章的开头。03 讲的是模型内部的循环（一次一个 token），这一页讲的是**模型外面**的循环（一次一个动作）。两层循环要分清：里面那层由模型完成，外面这层由程序完成。这个外层程序通常叫 harness，Claude Code 就是一个 harness。

## 画面布局

- **左上**：Think → Act → Observe 的环，中间是轮次计数。
- **左下**：5 行伪代码，当前执行的行会高亮。
- **右侧**：上下文面板，标题是 "CONTEXT (grows with every step)"，每一步都往里追加一行。

三块是同步的：环上亮哪个节点，代码就高亮哪一行，面板就多出对应的一条。排练时先看懂这个对应关系。

## 动画逐步解读

任务：**Fix the failing unit test in the Com module**

| 轮次 | 时间 | Think | Act（工具调用） | Observe（结果） |
|---|---|---|---|---|
| #1 | 2–5.5 s | Run the tests to see what fails | `Bash("ctest -R Com")` | 1 failed: test_Com_SendSignal |
| #2 | 5.5–9 s | Inspect the signal packing code | `Read("Com_Send.c")` | 412 lines |
| #3 | 9–12.5 s | Byte index is off by one: fix it | `Edit("Com_Send.c", line 218)` | file updated |
| #4 | 12.5–16 s | Verify the fix | `Bash("ctest -R Com")` | all 48 tests passed |
| 结束 | 约 17 s | （不再调用工具） | — | **ANSWER**: Fixed off-by-one in Com_Send.c:218 · tests pass |

讲解建议：第一轮讲慢一点，把三个节点和代码行的对应讲清楚；第二、三轮让动画自己跑；第四轮强调"它自己回去验证了"；最后指出退出条件。

## 伪代码

```python
while True:
    reply = llm(context)
    context += reply
    if not reply.tool_calls: break
    context += run(reply.tool_calls)
```

逐行解释：

| 行 | 含义 | 对应环上的节点 |
|---|---|---|
| `reply = llm(context)` | 把到目前为止的全部上下文交给模型，模型生成一段回复 | Think |
| `context += reply` | 模型的回复（包括它想做什么、要调用什么工具）记入上下文 | Think |
| `if not reply.tool_calls: break` | 回复里没有工具调用，说明模型认为做完了，退出 | 退出到 Answer |
| `context += run(reply.tool_calls)` | 程序真正执行工具，把结果记入上下文 | Act + Observe |

> 备注：原始动画里没有 `context += reply` 这一行，那样模型下一轮会看不到自己上一轮调用了什么，和右边的面板也对不上。单页版里已经补上。

## 需要真正搞懂的概念

### Agent = LLM + 工具 + 循环

三者缺一不可：

- 没有**工具**，模型只能说，不能做。
- 没有**循环**，模型只能做一步，看不到结果，也无法纠正。
- 循环让它能根据结果决定下一步。第 3 轮的"Byte index is off by one"不是事先计划好的，是读了文件之后才得出的。

### 是模型在决定流程

没有人写过"先跑测试，再读文件，再改代码"这样的脚本。这四步是模型每一轮自己决定的。程序只负责执行它要求的动作并把结果交回去。这是 Agent 和传统自动化脚本的根本区别：**流程不是预先写死的**。

### "Think" 也是生成出来的文字

面板里的 THINK 行不是另一种机制，它就是模型用 03 的循环生成的 token。同一次回复里既可以有思考文字，也可以有工具调用，所以每一轮的 THINK 和 TOOL 是同一个 `reply` 的两部分。

### 上下文只增不减

面板标题写得很明白："grows with every step"。4 轮下来，上下文里有 1 条用户消息、4 条思考、4 次工具调用、4 条结果、1 条答案。这里的结果都很短，但真实任务里一次 `Read` 可能就是几百行。这是 09 要解决的问题，这里先埋个伏笔。

### 退出条件

循环结束只有一个标准条件：**模型这一轮没有请求任何工具**。实际的 harness 还会加上保险：最大轮数、用户中断、权限被拒绝等。

### 出错了怎么办

工具执行失败（命令报错、文件不存在）时，错误信息同样作为结果放回上下文。模型下一轮看到错误，可以换个办法再试。这就是 Agent 有一定自我纠错能力的来源。

## 常见误解

- **"Agent 是一种新的模型"**：不是。模型还是那个只会预测下一个 token 的模型，Agent 是它外面那层程序。
- **"模型自己在运行命令"**：不是。模型只是在回复里写出"我想运行这个命令"，真正执行的是 harness。下一页专门讲这一点。
- **"循环次数是固定的"**：不是。这里是 4 轮，换个任务可能是 1 轮，也可能是几十轮。

## 听众可能会问

**Q：它会不会停不下来？**
有可能在一个问题上反复尝试。所以 harness 一般有最大轮数限制，用户也可以随时中断。

**Q：每一轮都要把全部上下文重新发给模型吗？**
是的。模型没有记忆（03 讲过权重是固定的），每一轮都要读到完整的历史。所以轮数越多、上下文越长，每一轮越贵。10c 的脚注和 09 都在讲这件事。

**Q：它怎么知道有哪些工具可以用？**
工具的说明也在上下文里。下一页讲。

**Q：会不会改错文件、执行危险命令？**
会有这个风险，所以 harness 有权限机制：哪些操作可以自动执行，哪些需要用户确认。决定权在 harness，不在模型。

## 自测

<details>
<summary>1. 用一句话区分 03 的循环和 04 的循环。</summary>

03 的循环在模型内部，每一圈生成一个 token；04 的循环在模型外部的程序里，每一圈是一次"模型回复 + 执行工具"。
</details>

<details>
<summary>2. 循环什么时候结束？</summary>

模型的回复里不包含工具调用时。
</details>

<details>
<summary>3. 为什么必须把模型自己的回复也追加到上下文里？</summary>

模型没有记忆，下一轮只能看到上下文。如果不记录它自己的回复，它就不知道自己调用过什么工具，结果也对不上。
</details>
