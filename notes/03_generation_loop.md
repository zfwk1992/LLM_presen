# 03 · Generation Loop（生成循环）

![Generation loop](../llm_agent_animations_single_page/03_generation_loop.gif)

> **一句话**：模型每次只做一件事——看完整个上下文，给词表里每个 token 打一个概率，选一个，接到末尾，然后重来。

## 在演讲里的位置

**这是整场演讲最重要的一页。** 后面的每一页都要回到这里：Agent 循环是在这个循环外面再套一层；工具调用是模型在这个循环里生成了特定格式的文本；模型大小和 effort 决定这个循环每一步多贵、一共跑多少步。如果只能让听众记住一页，就是这一页。

## 动画逐步解读

起始上下文是 `The ·ECU ·reads ·the ·CAN`，一共生成 4 个 token。

| 时间 | 画面 | 这时候讲什么 |
|---|---|---|
| 0–3 s | 上方是上下文，下方左边是一叠网络层，右边是候选列表 | 介绍三个区域：上下文、网络、输出 |
| 约 2 s | ① 上下文向下流过 Layer 1 … Layer N | "整个上下文过一遍网络，这叫一次前向传播" |
| 约 4 s | ② 右侧长出概率条 | "输出不是一个词，是对每个 token 的概率" |
| 约 6.5 s | `·bus 58%` 被高亮 | "这里选了概率最高的 bus" |
| 约 8.7 s | ③ `·bus` 沿虚线箭头飞回上下文末尾 | "选中的 token 接到上下文后面" |
| 11–13 s | 第二轮：`·and 34%`、`·every 27%`，被选中的是 `·every` | **关键点**："这次没有选概率最高的" |
| 15–18 s | ④ 第三轮：`·10 44%` 被选中 | "同样的过程再来一遍" |
| 18–21 s | 第四轮：`·ms 71%` 被选中 | "每个新 token 都成为下一轮的输入" |
| 约 21 s | 字幕：直到 `<end>` 或 `max_tokens` | "一直循环，直到模型输出结束符或达到上限" |

四轮的候选和结果：

| 轮次 | 候选（概率） | 选中 |
|---|---|---|
| 1 | bus 58%、frame 21%、message 12%、signal 6% | **bus** |
| 2 | and 34%、every 27%、to 19%、`.` 12% | **every**（不是最高的） |
| 3 | 10 44%、cycle 25%、20 12%、few 9% | **10** |
| 4 | ·ms 71%、·milliseconds 17%、ms 6%、·s 3% | **·ms** |

最终句子：`The ECU reads the CAN bus every 10 ms`

## 需要真正搞懂的概念

### 四个步骤

画面上的编号对应：

1. **前向传播**：整个上下文的向量（02）流过 N 层网络。每层由 attention（让每个位置参考其他位置）和 MLP（对每个位置做变换）组成。
2. **输出概率分布**：网络最后输出一个长度为 V 的向量，叫 logits（画面上的 `logits z`），词表里每个 token 一个分数。经过 softmax 变成概率，加起来等于 1。画面只列了前 4 名，下面有一行小字 "… every other token in the vocabulary"。
3. **选一个，追加**：按概率抽一个 token，接到上下文末尾。
4. **重复**：新的上下文比刚才多一个 token，回到第 1 步。

这种"自己的输出成为自己下一步的输入"的方式叫 **自回归（autoregressive）**。

### 权重是固定的

画面左下角写着 "Transformer · fixed weights"。对话过程中模型的参数**一个都不会变**，它不会因为和你聊天而学到东西。模型看起来"记得"前面说过的话，唯一的原因是那些话还在上下文里。这一点是后面 09 讲上下文管理的基础。

### 温度 T 和采样

公式 `p = softmax(z / T)` 里的 T 是温度：

- **T 很小**：分数差距被放大，概率最高的 token 几乎必然被选中，输出稳定、确定。
- **T 较大**：概率分布被拉平，低概率的 token 也有机会被选中，输出更多样。

第二轮故意演示了这一点：`and` 是 34%，但被选中的是 27% 的 `every`。这解释了一个日常现象：**同一个问题问两遍，答案可能不同**，因为每一步都是抽样，而不是查表。

### 第四轮里的 `·ms` 和 `ms`

候选列表里同时有 `·ms`（前面带空格）和 `ms`（不带空格）。它们是词表里两个不同的 token（见 01）。`10 ms` 和 `10ms` 两种写法都存在，模型在这里认为带空格的写法可能性更大。听众可能以为画面写重复了，可以主动解释。

### 为什么回答是一个字一个字蹦出来的

因为它确实就是这样生成的。流式输出不是界面特效，是生成机制本身。

### 什么时候停

- 模型输出了专门的结束 token（画面上的 `<end>`）。
- 达到调用方设置的输出上限 `max_tokens`。
- 遇到调用方指定的停止序列。

## 常见误解

- **"模型先想好整句话再写出来"**：不是。每一步只决定一个 token，写 `bus` 的时候还没有决定后面是 `every`。
- **"模型在数据库里查答案"**：不是。没有查询这一步，只有概率计算。这也是它会"一本正经地说错话"的原因：它生成的是**最像样的**后续，而不是**核实过的**事实。
- **"temperature 设成 0 就一定正确"**：只是更确定、更可重复，不代表更正确。

## 听众可能会问

**Q：每生成一个 token 都要把整个上下文重算一遍吗？**
概念上是的，每一步都依赖全部上下文。实现上会把前面算过的中间结果缓存起来复用，不用真的从头算，但上下文越长，每一步的代价仍然越高。

**Q：模型有多少层？**
商用模型一般不公布。画面里的 "Layer 1 … Layer N" 是示意。

**Q：它怎么知道该结束了？**
结束符也是词表里的一个 token。当模型认为"到这里最可能的下一个 token 是结束符"时，生成就停止。

**Q：所谓"思考"（thinking）是另一种机制吗？**
不是。思考过程也是用同一个循环生成的 token，只是这部分文字不作为最终答案展示。10b 那一页会回到这一点。

## 承上启下

- **上一页**：02 把 token 变成向量，这一页把向量送进网络。
- **下一页**：到这里模型只会写字。下一页讲怎样让它"做事"。
- **过渡句**："请记住这个循环。从现在开始，模型能做的事情没有再增加任何一样。接下来所有的新能力，都来自我们在这个循环**外面**加的东西。"

## 自测

<details>
<summary>1. 按顺序说出生成一个 token 的四个步骤。</summary>

前向传播 → 得到对整个词表的概率分布 → 选一个 token 追加到上下文 → 重复。
</details>

<details>
<summary>2. 为什么同样的输入可能得到不同的输出？</summary>

每一步是按概率抽样，不一定选概率最高的 token。温度越高，随机性越大。
</details>

<details>
<summary>3. 对话过程中模型的权重会变吗？它靠什么"记住"前文？</summary>

不会变。它靠的是前文仍然留在上下文里，每一步都重新读到。
</details>
