# 01 · Tokenization（分词）

![Tokenization](../llm_agent_animations_single_page/01_tokenization.gif)

> **一句话**：模型不认识文字，只认识整数。文本先被切成 token，每个 token 对应词表里的一个编号。

## 在演讲里的位置

这是第一页，作用是打掉一个直觉："模型在读我写的句子"。它读的不是句子，是一串整数。后面讲上下文窗口、成本、速度，单位全是 token，所以这一页要讲扎实。

## 动画逐步解读

| 时间 | 画面 | 这时候讲什么 |
|---|---|---|
| 0–3 s | 逐字打出 `Claude Code refactors the AUTOSAR module.` | "这是我们输入的一句话，对人来说是 6 个词" |
| 约 4 s | 句子裂成 10 个彩色方块 | "模型第一步是把它切成更小的单位，叫 token" |
| 5.5–9 s | 每个方块向下指向一个数字 | "每个 token 在词表里有一个固定编号" |
| 约 10 s | 上方出现 `"Claude" = 1 token` 和 `"AUTOSAR" = 3 tokens` | "常见词是一个 token，少见词被拆成几块" |
| 10–12 s | 深色条 `model input = [25734, 6307, …, 13]` | "模型真正收到的就是这串数字" |
| 约 13 s | `10 tokens`，以及词表大小的注释 | "6 个词，10 个 token" |

这句话被切成的 10 个 token：

```
Claude | ·Code | ·ref | actors | ·the | ·AUT | OS | AR | ·module | .
```

`·` 代表空格。注意空格是跟在 **后一个词的开头**，属于那个 token 的一部分。

## 需要真正搞懂的概念

### 为什么不直接按"词"切

- **按词切**：词表会无限大，新词、专有名词、拼写错误都会变成"未知词"。
- **按字符切**：词表很小，但一句话变得非常长，模型要花很多步才能拼出一个词。
- **按子词切（sub-word）**：折中。常见词整体保留，少见词拆成常见的片段。`AUTOSAR` 在通用语料里少见，所以被拆成 `AUT` + `OS` + `AR`；`refactors` 被拆成 `ref` + `actors`。任何字符串都能被表示，不存在"未知词"。

### BPE（Byte-Pair Encoding）是怎么得到词表的

画面上的说明文字提到了 BPE，它是最常见的子词算法。训练词表的过程：

1. 从最小单位开始（字节或字符），此时每个字符是一个 token。
2. 统计语料里哪两个相邻 token 最常一起出现，把它们合并成一个新 token，加入词表。
3. 重复第 2 步，直到词表达到预定大小（画面上写的典型范围是 5 万到 20 万）。

结果就是：出现得越频繁的片段，越可能成为一个完整的 token。词表训练好之后就固定了，这就是画面里 "fixed vocabulary" 的意思。

### 为什么这件事对使用者很重要

- **计费按 token**：输入和输出都按 token 数量收费。
- **上下文窗口按 token**：比如 "200K 上下文" 指的是 20 万个 token，不是字数。
- **速度按 token**：模型一次生成一个 token（见 03），输出越长越慢。
- **粗略换算**：英文大约 4 个字符一个 token，一个词平均略多于一个 token。中文、代码、专有名词的比例不同，通常同样的内容 token 数更多。

### 模型看不到字母

模型收到的是 `25734`，不是 `C-l-a-u-d-e` 六个字母。这解释了一个常被拿来嘲笑模型的现象：数单词里有几个某字母、把字符串倒过来写，这类任务对它并不天然容易，因为它根本没有直接看到字符。

## 常见误解

- **"一个 token 就是一个词"**：不对。画面里 6 个词变成了 10 个 token。
- **"token ID 的数值大小有含义"**：没有。ID 只是编号，`25734` 和 `25735` 之间没有任何语义关系。语义在下一页的向量里。
- **"所有模型的分词都一样"**：不一样。每个模型家族有自己的分词器和词表，同一句话在不同模型上的 token 数和 ID 都不同。画面上的 ID 是示意值，下方有小字 "IDs here are illustrative"。

## 听众可能会问

**Q：中文是怎么切的？**
同样的机制。中文没有空格，分词器按字节序列里学到的常见片段切。常用字词可能是一个 token，生僻字可能被拆成多个。总体上，表达同样的内容，中文的 token 数往往不比英文少。

**Q：怎么知道我的文本有多少 token？**
各家 API 都提供计数接口，Claude Code 里可以用 `/context` 看当前上下文的占用。

**Q：专业术语被拆碎了，模型还能理解吗？**
能。拆开的片段在后面的网络层里会被重新组合理解（见 02、03）。被拆成多个 token 只意味着它占的位置多一点，不代表模型不认识它。

**Q：空格为什么算在 token 里？**
这样 ` Code`（前面带空格，出现在句中）和 `Code`（不带空格，出现在行首或紧跟其他字符）是两个不同的 token，模型能区分词的边界。03 那一页的候选词里同时出现 `·ms` 和 `ms`，就是这个原因。

## 自测

<details>
<summary>1. 为什么 AUTOSAR 是 3 个 token，而 Claude 是 1 个？</summary>

词表是按片段出现频率训练出来的。在训练语料里足够常见的字符串会被合并成一个 token，少见的字符串只能由更短的常见片段拼出来。这是示意，具体切法取决于分词器。
</details>

<details>
<summary>2. token ID 47270 比 279 大，说明什么？</summary>

什么也不说明。ID 只是词表里的位置编号，没有大小意义。
</details>

<details>
<summary>3. 说出三个以 token 为单位计量的东西。</summary>

费用、上下文窗口容量、生成速度（以及输出长度上限 `max_tokens`）。
</details>
