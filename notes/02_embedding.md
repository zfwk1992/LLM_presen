# 02 · Embedding（嵌入向量）

这个主题有两页。

![Embedding lookup](../llm_agent_animations_single_page/02a_embedding_lookup.gif)

![Embedding space](../llm_agent_animations_single_page/02b_embedding_space.gif)

> **一句话**：每个 token ID 在一张学出来的大表里对应一行数字，这行数字就是它的向量；意思相近的 token，向量的方向也相近。

## 在演讲里的位置

01 把文字变成了编号，但编号没有含义。这两页回答"含义存在哪里"：存在向量里。第一页讲**怎么得到**向量（查表），第二页讲向量**有什么性质**（相近的意思靠在一起）。06 讲 RAG 时会再次用到第二页的余弦相似度。

## 第一页：查表（02a，8.0 s）

| 时间 | 画面 | 这时候讲什么 |
|---|---|---|
| 0–2 s | 左边是 token `·module`（ID 4295），右边是矩阵 E | "上一页最后那个 4295，现在拿它去查一张表" |
| 约 3 s | 箭头指向第 4295 行，这一行被框出 | "ID 就是行号，直接取出这一行" |
| 约 5 s | 右侧出现 `x = E[4295] ∈ ℝᵈ` 和一行数字 | "这一行就是这个 token 的向量，一串 d 个数字" |
| 6.5–8 s | 注释：d 是几千维，训练中学到 | "这些数字不是人设计的，是训练出来的" |

要点：

- **矩阵 E 的形状是 V × d**。V 是词表大小（上一页说的 5 万到 20 万），d 是每个向量的维数（几千）。这张表本身就是模型参数的一部分。
- **"Embedding"就是查表**。没有计算，只是按行号取一行。画面里的 `E[4295]` 就是数组下标访问。
- **数字是学出来的**。训练开始时这张表是随机数，训练过程不断调整，直到这些向量对预测下一个 token 有用。

## 第二页：向量空间（02b，8.8 s）

| 时间 | 画面 | 这时候讲什么 |
|---|---|---|
| 0–2 s | 一个坐标系，逐个出现 CAN、LIN、FlexRay、Ethernet | "把每个向量看成空间里的一个点" |
| 2–5 s | 依次出现动物、制动、软件三组 | "训练之后，意思相近的词自然聚在一起" |
| 约 6 s | 右侧出现余弦相似度公式，原点画出 CAN 和 LIN 两个箭头 | "相似度用两个向量的夹角衡量" |
| 约 7 s | `CAN ↔ LIN 0.97 similar` | "夹角很小，接近 1" |
| 约 8 s | 画出指向 cat 的箭头，`CAN ↔ cat 0.01 unrelated` | "接近垂直，接近 0，说明无关" |

四个聚类：

- **vehicle buses**：Ethernet、FlexRay、CAN、LIN
- **animals**：horse、cat、dog
- **braking**：brake、ABS、ESP
- **software**：function、module、component

### 余弦相似度

```
cos θ = a · b / (‖a‖ ‖b‖)
```

- 分子是两个向量的点积，分母是两个向量长度的乘积。结果只和**夹角**有关，和向量长短无关。
- 取值范围 −1 到 1。接近 1：方向几乎相同，意思相近。接近 0：几乎垂直，无关。接近 −1：方向相反。
- 画面右下角的总结："Direction encodes meaning: small angle → related concepts"（方向编码含义，夹角小说明概念相关）。

## 需要真正搞懂的概念

### 没有人告诉模型 CAN 和 LIN 是一类

模型的训练目标只有一个：预测下一个 token。CAN 和 LIN 在文本里出现的上下文很像（"… bus"、"… frame"、"… transceiver"），为了预测得准，模型自然会给它们相近的向量。聚类是训练的**副产品**，不是人工标注的。

### 二维只是示意

真实向量有几千维，画不出来。画面标题写的是 "2-D projection"（二维投影），是把高维空间压到平面上看个大概。讲的时候要说一句，否则听众会以为真的只有两个数。

### 输入向量和"理解"不是一回事

这一页讲的是**输入层**的向量：同一个 token 永远查到同一行。但 `CAN` 既可以是总线，也可以是英语里的"能"。区分这两个意思靠的不是这张表，而是后面的 Transformer 层：每一层都会根据上下文里的其他 token 修改这个向量。所以进网络时 `CAN` 的向量是固定的，出网络时它已经带上了"这里指的是总线"的信息。这一步在 03 的画面里是那一叠 "attention + MLP" 层。

### 还缺一样东西：位置

查表得到的向量不含顺序信息。"ECU reads CAN" 和 "CAN reads ECU" 查出来是同一组向量。实际模型会另外把位置信息编码进去，动画里没有画这一步，被问到时知道有这回事就行。

### 和 RAG 里的 embedding 是什么关系

容易混淆的两个东西：

| | 这一页讲的 | 06 RAG 里用的 |
|---|---|---|
| 输入 | 一个 token | 一整段文字 |
| 输出 | 一个向量 | 一个向量 |
| 来自 | LLM 内部的 embedding 表 | 专门的 embedding 模型 |
| 用途 | 作为网络的输入 | 做语义检索 |

思想相同（意思相近则向量相近），但是两个不同的模型部件。

## 常见误解

- **"每一维代表一个明确的属性"**：通常不是。不存在"第 17 维 = 是否是总线"这样的对应，含义是分散在很多维度里的。
- **"向量是人工设计的"**：不是，全部来自训练。
- **"相似度高 = 同义词"**：不一定。向量相近表示出现的语境相近，反义词（比如 high / low）也经常离得很近。

## 听众可能会问

**Q：d 到底是多少？**
不同模型不同，量级是几千。商用模型一般不公布具体结构。

**Q：这张表有多大？**
V × d 个数。按 10 万词表、几千维估算，是几亿个参数的量级，在整个模型里只占一小部分。

**Q：为什么用夹角而不是距离？**
夹角不受向量长度影响，只看方向。在高维空间里，这通常比直线距离更能反映语义关系。

**Q：图里 CAN 和 cat 的相似度是 0.01，为什么不是负数？**
这是示意数值，想表达的是"接近 0，即无关"。

## 承上启下

- **上一页**：01 得到一串整数。
- **下一页**：现在每个 token 都是一个向量了。下一页把这些向量送进网络，看模型怎样用它们算出下一个 token。
- **过渡句**："到这里，一句话变成了一组向量。接下来才是模型真正开始工作的地方。"

## 自测

<details>
<summary>1. "embedding lookup" 具体做了什么运算？</summary>

没有运算，只是用 token ID 作为行号，从矩阵 E 里取出一行。
</details>

<details>
<summary>2. 余弦相似度为 0.97 和 0.01 分别意味着什么？</summary>

0.97：两个向量夹角很小，方向几乎一致，概念相关。0.01：几乎垂直，概念无关。
</details>

<details>
<summary>3. 同一个 token "CAN" 在不同句子里，查表得到的向量一样吗？模型怎么区分它的不同含义？</summary>

查表得到的向量完全一样。区分含义靠后面的 Transformer 层，它们根据上下文修改每个位置的向量。
</details>
