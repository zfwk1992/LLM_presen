# 02c · 从 token 到下一个 token：完整路径

![The whole path](../llm_agent_animations_single_page/02c_whole_path.gif)

> **一句话**：n 个 token 变成 n 个向量，一起进入网络；网络输出 n 个向量，只取最后一个，算出词表里每个 token 的概率；选一个 token，接到输入末尾，再来一遍。

这一页专门回答 embedding 和生成循环之间的几个疑问。先给结论，再看画面。

## 几个疑问的直接回答

### 1. 得到向量之后，要先计算相似度吗？

**不用。相似度不是这条路径上的任何一步。**

向量查出来之后直接送进网络，中间没有比较、没有筛选、没有任何计算。画面上 "vectors" 和 "Transformer" 之间那个橙色的标注 **all together, straight in** 说的就是这件事。

02b 那一页展示的余弦相似度，是在**描述**这些向量的一个性质（意思相近的词，向量方向相近），好比在解释"为什么用向量来表示词是合理的"。它是一个旁白，不是流程。02b 的画面右下角现在加了一个橙色的说明框 "Not a step in the pipeline"，就是为了避免这个误会。

### 2. LLM 接收的是"整个向量"吗？

**接收的是所有 token 的向量，一个不少，同时进去。**

- 输入 5 个 token，就有 5 个向量同时进入网络。
- 每个向量是 d 个数字（d 是几千）。所以网络的输入是一张 **5 × d** 的数字表。
- 不是只送最后一个，也不是把 5 个合并成一个。

### 3. 然后算出一个 token，再把它放回输入？

**对，但中间有两小步值得看清楚。**

1. 网络输出的也是 5 个向量（进去几个，出来几个）。**只用最后一个。**
2. 这最后一个向量被换算成**词表里每个 token 的概率**（约十万个数字，加起来等于 1），不是直接得到一个 token。
3. 从这个概率分布里**选出一个** token。
4. 这个 token 被接到输入末尾。下一轮，输入是 6 个 token、6 个向量，整个过程重来。

所以你的理解可以修正成一句话：**"LLM 接收所有 token 的向量，算出下一个 token 的概率分布，选一个，放回输入末尾，循环。"**

### 4. 一个输出向量，为什么对应那么多个可能的 token？

因为**输出向量本身不是一个 token**，它只是 d 个数字，可以理解成网络对"下一个词应该是什么样"的一个描述。要把这个描述变成具体的 token，需要拿它去和**词表里每一个 token 的向量**逐个比对：

- 和 `·bus` 的向量比，很匹配，分数高。
- 和 `·frame` 的向量比，比较匹配，分数中等。
- 和 `·cat` 的向量比，不匹配，分数很低。
- ……词表里约十万个 token，每一个都比一次，得到约十万个分数。

这些分数再换算成加起来等于 1 的概率。所以是：**1 个输出向量 → 和词表里每个 token 各比一次 → 每个 token 一个概率 → 从中选 1 个**。

画面右边的面板现在就是这样画的：每一行是一个候选 token，中间一列是这个 token 自己的向量，右边是匹配后的概率。可以看到 `·bus` 那一行的向量颜色和被橙色框出的输出向量几乎一样，所以它的概率最高。面板标题是 *matched against every token*，底下一行写着 *one row for each of the ~100,000 tokens*。

你的直觉"每个输出向量对应一个 token"其实也是对的，只是对应的方式是这样：

| 输出向量 | 它预测的是 | 需要吗 |
|---|---|---|
| 第 1 个（`The` 的位置） | 第 2 个 token | 不需要，已经知道是 `·ECU` |
| 第 2 个（`·ECU` 的位置） | 第 3 个 token | 不需要，已经知道是 `·reads` |
| 第 3 个 | 第 4 个 token | 不需要 |
| 第 4 个 | 第 5 个 token | 不需要 |
| **第 5 个（`·CAN` 的位置）** | **第 6 个 token** | **需要，这是唯一未知的** |

每个位置的输出向量都在预测"它后面的那个 token"。前 4 个预测的是已经存在的 token，没有用；只有最后一个预测的是新的。这就是字幕 ④ 说的 *Each output vector predicts the token after it: only the last is new*。

### 5. 训练完之后，向量空间就固定了吗？相似的向量距离近吗？

**对，两点都对。**

- **固定**：embedding 表是模型权重的一部分，训练结束后就不再变。推理时每个 token 永远查到同一个向量。
- **相似的靠得近**：训练的结果是，出现语境相近的 token，向量在空间里也相近。

一个小的精确化：衡量"近"通常看的是**方向**（夹角、余弦相似度），而不是直线距离。在几千维的空间里，方向比距离更能反映语义关系。日常理解成"离得近"没有问题。

还有一点容易忽略：这个"相近"不是人规定的，也不是训练的目标。训练的目标只有"预测下一个 token"，相近是为了达到这个目标自然形成的结果。

### 6. 我的提示词是一个 token 一个 token 喂进去的吗？

**不是。提示词的所有 token 是一次性、同时进入网络的。**

写了一段 1000 个 token 的提示词，过程是这样：

1. 1000 个 token 全部查表，得到 1000 个向量。
2. 这 1000 个向量**一起**进入网络，做**一次**前向传播（forward pass）。
3. 取最后一个位置的输出向量，得到第 1001 个 token 的概率，选出一个。
4. 把这个新 token 接到末尾，再做**一次**前向传播，得到第 1002 个。
5. 如此重复。

所以前向传播的次数取决于**生成了多少个 token**，和提示词有多长无关：

| 情况 | 前向传播次数 |
|---|---|
| 提示词 1000 个 token，回答 200 个 token | 约 200 次 |
| 提示词 10 个 token，回答 200 个 token | 约 200 次 |
| 提示词 1000 个 token，回答 1 个 token | 1 次 |

提示词变长，不会增加次数，但会让**每一次**的计算量变大（要处理的向量更多）。

这解释了两个日常现象：

- **读得快，写得慢。** 模型"读"完很长的提示词只需要一次前向传播，各个位置是并行计算的；而"写"每个 token 都要单独一次。
- **输出比输入贵。** 各家的定价里，输出 token 的单价都比输入 token 高，原因就在这里。

画面上，Transformer 的框里现在有一个紫色标签：第一轮是 **forward pass #1**，`·bus` 接回输入后变成 **forward pass #2**，下面一行写着 *whole input at once*。

一个实现细节，被问到时知道即可：第二次前向传播时，前 5 个 token 在各层的中间结果和第一次完全一样，所以实际系统会把它们缓存下来复用，只新算第 6 个 token 的部分。概念上仍然是"整个输入再过一遍网络"，只是不做重复劳动。

## 用具体数字走一遍

输入是 `The ECU reads the CAN`，画面从左到右：

| 步骤 | 这一步手里的东西 | 数量 |
|---|---|---|
| tokens | `The` `·ECU` `·reads` `·the` `·CAN` | 5 个 token |
| token IDs | 791、29012、16181、279、20644 | 5 个整数 |
| vectors | 5 条彩色的数字条 | 5 × d 个数字 |
| Transformer | N 层 attention + MLP | 权重固定 |
| output vectors | 5 条数字条，只有最后一条被框出 | 5 × d 个数字，只用最后的 d 个 |
| matched against every token | 最后那个向量与词表里每个 token 的向量各比一次：·bus 58%、·frame 21%、·message 12%、·signal 6% … | 词表里每个 token 一个概率 |
| picked | `·bus` | 1 个 token |

然后 `·bus` 沿着橙色虚线回到最左边，成为第 6 个 token。它同样被查出 ID（5951）、查出向量，和前面 5 个一起再进一次网络。这一次被框出的是第 6 个输出向量，用它来预测第 7 个 token。

画面上的 ID 是示意值。概率的四个数字和 03 第一轮完全一致，所以这一页讲完可以直接接 03。

## 几个容易想错的地方

- **"向量进去之前要先做点什么处理"**：不用。查表得到的向量（加上位置信息）就是网络的输入。
- **"网络只看最后一个 token"**：不是。所有 token 的向量都进去，网络内部让它们互相交换信息（02d 讲的 attention）。只是**输出**只取最后一个位置的。
- **"前面几个输出向量白算了"**：在预测下一个 token 这件事上，它们确实不被直接使用。但在网络内部的每一层，后面的位置都要读取前面位置的信息，所以它们是必需的中间结果。
- **"网络直接输出一个 token"**：不是。它输出的是概率分布，"选哪一个"是网络之后的一步（03 讲的采样）。
- **"每一轮网络都不一样"**：网络完全一样。画面上 Transformer 下面写着 *same weights every round*。每一轮变的只有输入多了一个 token。

## 一个帮助理解的类比

把网络想成一个**只会做一道题的考生**：给他一段没写完的话，他给出"下一个词可能是什么"的概率表。

- 你把 5 个词交给他（实际交的是 5 个向量）。
- 他读完全部 5 个词，给你一张表：bus 58%，frame 21%……
- 你按这张表抽一个词，写到那段话后面。
- 你把 6 个词重新交给他。他不记得上一轮，每次都是从头读一遍。

"相似度"在这个过程里的角色是：这位考生之所以读得懂，是因为他学过的"词的表示方式"里，意思相近的词本来就靠得近。那是他的知识结构，不是他答题时的一个步骤。

## 自测

<details>
<summary>1. 输入 5 个 token 时，进入网络的是什么？数量是多少？</summary>

5 个向量，每个 d 个数字，共 5 × d 个数字。所有向量一起进入。
</details>

<details>
<summary>2. 网络输出了 5 个向量，预测下一个 token 用的是哪个？它被变成了什么？</summary>

只用最后一个。它被换算成词表里每个 token 的概率。
</details>

<details>
<summary>3. 余弦相似度在这条路径的哪一步？</summary>

不在任何一步。它只是用来描述向量空间的性质。
</details>

<details>
<summary>4. 第二轮和第一轮相比，什么变了，什么没变？</summary>

变了：输入多了一个 token（从 5 个变成 6 个），用来预测的是第 6 个输出向量。没变：网络的权重，以及整个流程。
</details>
